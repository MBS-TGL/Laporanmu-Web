# Batch Berikutnya: Modul Skorsing & Pembinaan di Rumah

## Context
Modul terbesar tersisa dari V1 — melengkapi siklus disiplin: **poin → pelanggaran berat → skorsing → checklist ibadah harian di rumah (diisi wali) → tugas guru dinilai → verifikasi pembina**. Aset V1 (`supabase/migrations/20261103000000_suspension.sql`) berisi 8 tabel + RLS deny-by-default + 4 RPC publik (token sha256 + rate limit) + seed 24 template checklist — **diadaptasi ke konvensi V2**, bukan ditulis ulang.

## Adaptasi dari migration V1 → `0014_skorsing.sql`
Ambil struktur V1, dengan penyesuaian:
- Helper role V1 (`is_suspension_admin/staff`) → **pakai helper V2 yang sudah ada** (`has_any_role`, `is_staff` dari 0013) + satu helper baru `is_suspension_task_owner`
- Trigger `_suspension_touch` → pakai `set_updated_at` V2
- Section feature_flags (V1) → **dibuang** (V2 tak punya tabel flag; akses dijaga role)
- `audit_logs` inserts di RPC → **kompatibel** dengan skema audit V2 (0013)
- 8 tabel: `suspension_log_templates`, `suspensions` (reason_summary internal, jangan pernah ke wali), `suspension_tokens` (sha256 hash only), `suspension_tasks`, `suspension_task_submissions` (foto base64 max 6/12, 2MB each), `suspension_daily_logs`, `suspension_followups`, `suspension_token_attempts` (rate limit)
- 4 RPC publik utk wali (grant ke `public`): `validate_suspension_token`, `get_suspension_day`, `save_suspension_log`, `submit_suspension_task` — **disalin dengan penyesuaian minimal** (mereka sudah security-definer + deny-by-default)
- Seed 24 template checklist (4 blok: dinihari/pagi/sore/malam + varian weekend)
- RLS staff: tulis suspensions/tokens/daily_logs = admin; tasks = staff (owner-edit); submissions = staff, grading = owner/admin; followups insert staff

## Fitur frontend — `src/features/suspension/`

### 1. Staff — `SkorsingPage.tsx` (`/skorsing`, nav Kesantrian)
- Kartu statistik: aktif, selesai, terlambat-kan wali (log harian bolong), urgensi tugas
- Tabel suspensi: santri, jenjang, periode, status (aktif/selesai/dibatalkan), progress log harian, aksi → detail
- Form terbitkan: pilih santri, tanggal mulai/selesai (jenjang auto dari grade), alasan internal, (opsional) link ke `reports` (poin) — hanya admin
- Aksi status: Selesaikan / Batalkan (admin)

### 2. Staff — `SkorsingDetailPage.tsx` (`/skorsing/:id`)
- **Info & token**: generate token (raw ditampilkan SEKALI + tombol copy link `/skorsing/<token>`), daftar token (prefix, kedaluwarsa, use_count), cabut token
- **Tugas**: CRUD tugas per guru (subject, title, description, due_date) — owner edit
- **Submissions**: review bukti foto (tampil base64), beri **nilai 0–100 + komentar** (owner/admin)
- **Log harian**: kalender ringkasan per tanggal (terisi/bolong) + detail entries
- **Followups**: catat verifikasi mingguan (telepon/WA/kunjungan)
- Audit logger di semua mutasi staff

### 3. Publik — `SuspensionWaliPage.tsx` (`/skorsing/:token`, tanpa login)
- Validasi token via RPC → header: nama santri, kelas, periode, pilihan tanggal (days array)
- Per tanggal: `get_suspension_day` → checklist 4 blok dengan input type (check/choice/text/surah/wafa/tugas_ref) → `save_suspension_log`
- Daftar tugas → form kirim bukti: upload foto (kompres canvas <500KB, maks 6) + catatan → `submit_suspension_task`; tampilkan status/score/komentar guru
- Tanpa reason_summary (privasi) — error RPC ditampilkan ramah
