# Taste
- For UI styling, use the design-system theme tokens (e.g. Ant Design `theme.useToken()`) for colors, radii, and borders instead of hardcoded values, so dark mode stays correct. Confidence: 0.7
- Expects adjacent UI controls to be visually consistent in size: filter chips/tags should match the height and radius of neighbouring inputs (e.g. the search bar), and secondary/footer buttons must be the same size as the primary button next to them, not left at a compact `size="small"` default. Confidence: 0.7
- For print/export features, expects WYSIWYG fidelity: the printed output must look identical to the on-screen preview (same page height, footer placement, typography), and rebuilt screens must match the existing v1 implementation exactly rather than an approximate redesign. Confidence: 0.85
- Modals must use the project's shared wrapper components (`AppModal` + `ModalFooter`) rather than raw Ant Design `Modal`, so mobile bottom-sheet behavior and consistent header/footer are preserved everywhere. Confidence: 0.8
- For official/certified documents (raport, surat, printouts with QR/numbering), prioritize porting the existing template verbatim over visual restyling; decorative treatments and motion polish belong only in the surrounding app shell (list, toolbar), never on the paper itself. Confidence: 0.75
- On generated documents, personal names must be rendered in Title Case, not ALL CAPS (while keeping official abbreviations/school acronyms and degree suffixes capitalized). Confidence: 0.6
- Treats mobile as a separate layout, not a shrunken desktop one: mobile view must have its own sizing, grid, navigation, and modal state, and expects this rule to be written into the project's design/agent docs (DESIGN.md/SKILLS.md/AGENTS.md) so it applies to all future work. Confidence: 0.8
- Prefers UI actions stay visible at all times rather than being conditionally hidden: when an action isn't applicable (e.g. "Reset default" while settings are already default), keep the button rendered and `disabled` instead of removing it, so the layout doesn't shift and users always know the control exists. Confidence: 0.65
- Prefers concise, structured end-of-task reports: a short list of what changed, what was skipped (with reasons), and assumptions made. Confidence: 0.65
- Prefers visual comfort over maximum density: when more rows must fit, enlarge the panel (a little page scroll is acceptable on short screens) rather than shrinking row padding, avatar size, and font sizes — overly cramped lists are rejected as visually bad, even when handed the row count for. Confidence: 0.75
- Rejects auto-shrinking typography to force content into one line ("teks menciut" = ugly); prefer a fixed, readable font size with natural wrapping, and widen the column / add clear padding instead of squeezing. Confidence: 0.8
- Prefers Indonesian-context defaults to be the out-of-the-box setting for generated school reports: language mode defaults to Bahasa Indonesia and paper size defaults to F4, rather than being derived from URL params or left at A4. Confidence: 0.5
- For fullscreen/focus preview of a document, expects the surrounding app to be visually suppressed — a dimmed scrim backdrop above the header/nav so only the document is visible — with zoom defaulting to 100% (actual size) instead of fit-to-screen; "Fit" stays available as an explicit toggle. Confidence: 0.6
- Expects side-by-side content panels (e.g. list panel + preview panel) to fill the available viewport height; fixed `calc(100vh - N)` height caps are treated as a defect, so heights should be measured from the panel's position to the bottom of the viewport. Confidence: 0.55
- Expects error screens to be audience-aware: developers get real diagnostics (stack trace, component stack, message, where it happened, copy-details action), while non-developer end users get a clean, non-technical fallback page instead of raw error text. Confidence: 0.7
